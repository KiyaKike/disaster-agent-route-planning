# 下一步：18 对外部事件影像的可行性试验

当前应做的是**验证“固定感知器的搜索效用能否跨灾害迁移”是否值得研究**。此前加深规划没有超过简单变化排序，先停止在原 72 场景上继续调参。本阶段固定了新事件候选、18 对样本和实验协议；尚未下载这些影像、完成人工标注或产生新成绩，也没有选定新算法。

来源固定为 [EBD figshare v2](https://api.figshare.com/v2/articles/25285009/versions/2)。其官方记录说明影像为灾前后 512×512 RGB，标注由机器生成并经人工后处理。它适合作为候选影像池；发布格式尚未证明可追溯的逐栋实例身份，不能直接把掩膜连通分量当成真实建筑。原影像条款、配准、地理范围和重复检查仍待核对。不同事件名称不等于已经通过独立数据准入。

选择仅使用 `SHA256(固定版本｜固定种子｜事件｜样本ID)`，没有读损伤、目标数量或预测成绩；完整公式见 `cohort_selection_protocol.json`。阴性、模糊、缺目标或技术失败均不换图。这 18 对一旦用于可行性检查，永久归开发用途，不能再改名为最终确认集。旧 216 候选和分组保持原样。

## 接下来实际做什么

1. **核对条款，提取固定的 36 张 RGB。** 先写有界成员提取协议，再按清单读取，校验头部、压缩长度、CRC 和 SHA256；不整包下载、不自动补图。索引显示这些 PNG 的压缩数据共 13,691,009 字节，提取阶段上限 128 MiB。目前下载队列全部关闭；本阶段未读取任何影像或损伤掩膜载荷。
2. **先形成能核查的逐栋人工标注。** 对全部 18 对整图检查，记录建筑轮廓、场景内 ID、可见损伤级别和 unknown；首轮不看模型预测或 EBD 掩膜，由另一名复核者处理分歧。先计时每事件第一对，再估算全部工作量；尚未落实或完成的人工工作不能声称已有真值。空表不是阴性场景，人工影像判读也不等于现场结构安全鉴定。
3. **标注与测量核验通过后，先跑固定感知器。** 上限 576 次局部观察，先用本机 CPU/MPS，不租 GPU、不训练控制器。先看每事件有多少可标、可检出的严重受损建筑，再决定是否进入搜索回放。某事件没有可检出目标时保留结果，不能补挑阳性影像。

对应文件：`rgb_download_queue_disabled.json`、`annotation_queue_unfilled.json`、`annotation_schema_notes.json`。人工记录的结构校验器能阻止空表、重复实例 ID、缺失哈希等错误，但不能证明有人真实复核或标注准确。

## 实验怎么固定

512×512 图像按 128×128 切为 **4×4 格**；主预算 **8**，初查成本 1、升级成本 2，混合质量。免费粗图用 **64×64 BOX**，保持与旧实验相同的 8 倍降采样及每格 16×16 粗图像素。旧实验是 1024×1024、8×8 格、粗图 128×128、预算 32，因此不能直接比较两批的绝对发现数。旧 8×8 runner 不能原样用于新数据，需另写尺寸适配并先验证。

感知权重、局部退化、严重损伤声明和匹配规则维持冻结。若测量通过，后续只做预定描述性对照：随机初查、原始变化排序、简单阴性复核、冻结来源数量贪心、一阶段及两阶段成本规划适配。数量模型只使用旧 `development_fit`，不在新事件上改参数或选来源拟合。三事件分别报告，再等权平均；种子先在场景内平均，不能当独立灾害。

先回答两个可失败的问题：**新事件是否提供可信的目标发现机会？冻结来源效用是否存在事件相关失配？** 感知器无发现机会就先解决测量；没有效用失配证据就不据此提出新迁移方法。即使看见失配，也须另定一个可实现的适应假设及独立评价计划，不能把评价真值当在线免费反馈。

完整顺序、门槛、主次设置及停止条件见 `prospective_feasibility_v3.json`。这是一份前瞻性可行性协议，没有替换有效 v2.2 合同，也没有开放验证／确认评分。
