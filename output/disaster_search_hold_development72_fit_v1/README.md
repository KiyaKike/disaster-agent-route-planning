这是遍历全部网格的工程匹配代理，**不是预算 32 的策略成绩**。本轮 1,216 个目标均进入至少一个格的可见目标集合；原图/模糊覆盖代理约为 88.8%/14.6%。Mexico 既有严重目标稀少的问题，也有固定感知器未匹配的问题；现有缓存下任何搜索策略都无法找到这 3 栋。该事件仍保留在原定事件等权统计中，不因这个结果删除或替换，也不能把它当作成功复现的第三种灾害。

按预先固定的可见轮廓覆盖 5%/10%/25% 重算，原图匹配分别为 1,086/1,080/1,069，模糊为 190/178/158。主要阈值仍为 10%，没有按结果换阈值。

原图共有 1,588 次“观察—建筑”匹配，其中 508 次为重复匹配；模糊为 226 次匹配、48 次重复。不能用 1,588 当作不同建筑发现数。跨格新增收益仍是后续规划需要处理的近似问题，上一轮的边缘折扣已经证明“少重复”不等于“多发现”。

已知真值格中，原图 TP/FN/FP/TN 为 614/106/40/3,816；模糊为 143/577/2/3,854。每种条件均排除 32 个不确定格。格检出、建筑去重发现与像素精度是不同指标，不相互替代。

## 复核与数量模型

沿用六样本阶段的固定模型、预处理、四严重像素声明规则和 `raster_visibility_v2`。9,216 次观察中复用原六样本的 768 次，新增 8,448 次；RGB 和缓存哈希均核对。预测命令不读取标签内容，评价由另一条命令执行。MPS 观察循环约 521.3 秒，全部观察单次中位数约 53.7 毫秒，未租 GPU。

同格数量模型拟合 4,576 对已知真值观察，排除 32 对未知格。成对 2×2 似然每种结果用 0.5 伪计数，公开粗图线索分四档，各档数量均值向全局均值收缩 8 个伪格；参数未根据本轮结果另行选择。相关模糊/原图结果不作为独立边际似然累乘。

| 已观察模糊结果 | 已知格数量 | 原图复核新增的同格匹配建筑均值 |
|---|---:|---:|
| 阴性 | 4,431 | 0.2487 |
| 阳性 | 145 | 1.8069 |

新增数量使用 `native_matched - blurred_matched`，不是原图总数量。这个结果支持保留“模糊阳性后仍可复核”的动作资格；不能一报阳性就自动终止。但这些是开发数据上的同格统计，尚未减去已在其他格发现的建筑，**不能直接当作实际全局新增收益，也不证明始终应该复核阳性格**。后续仍要按成本和预算比较。

参数保存在 `component_parameters.json`，没有真实建筑 ID；真实 ID 仅在离线拟合器和评价器使用。未知真值格没有填成已知负例。

## 下一轮固定比较

先复用这批缓存，在开发侧跑以下对照：

1. 随机、行优先覆盖、粗图先验排序，判断排序本身的价值。
2. 同预算的更多初查与初查/复核组合，报告实际复核次数；模糊阳性复核保留为明确消融。
3. 目标存在性效用与同格新增数量效用，使用相同动作、成本和观测。
4. 图像可用面积控制：初始特征只能来自相同的公开粗图，报告大面积黑边的影响；不偷偷使用未来高分辨率裁块或按真值删格。

主要设置继续为质量混合、预算 32、复核成本 2；完整报告预算 8/16/32、三质量条件与复核成本 1/2/4。每条轨迹均按 5%/10%/25% 覆盖重算，场景内先平均种子，再平均事件，另列各事件和空间组。

完整预算简单基线、存在性消融与 ENS/MF-ENS/rollout 强对照尚待完成。只有明确这些对照后，才考虑是否有剩余收益值得设计新控制机制；当前不训练新控制器，不打开验证/最终确认结果。

## 复现评价与拟合

```bash
work/disaster_search/.venv_inference/bin/python work/disaster_search/run_hold_development_perception.py \
  --data output/disaster_search_hold_development72_v2 \
  --design output/disaster_search_v2_design \
  --model work/disaster_search/attachments/external/huggingface/changeos_swint \
  --probes output/disaster_search_hold_probes_v1 \
  --probe-perception output/disaster_search_hold_probe_perception_v1 \
  --out output/disaster_search_hold_development72_perception_v1 --stage evaluate
work/disaster_search/.venv_inference/bin/python work/disaster_search/fit_hold_development.py \
  --perception output/disaster_search_hold_development72_perception_v1 \
  --data output/disaster_search_hold_development72_v2 \
  --design output/disaster_search_v2_design \
  --out output/disaster_search_hold_development72_fit_v1
```

首次预测将第一条命令的 `--stage evaluate` 改为 `--stage predict`；会先核对并复用六样本缓存，再运行新增场景。已完成的记录会校验后恢复，不重复推理。各阶段协议、日志与源代码快照分别保留。
