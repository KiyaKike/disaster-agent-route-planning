## 没有人工资源，后续怎么做

保留已固定的 18 对作为可行性／开发数据，先使用 **EBD 发布的语义掩膜作为参考标签**，评价预算内覆盖的严重受损像素面积，不从连通分量制造建筑实例。EBD 声明标注经过机器生成和人工后处理；这不等于我们新做了人工复核或取得独立现场真值。

下一步顺序已写入 `prospective_area_reference_v3_1.json`：

1. 给同一 18 对的灾后掩膜另立精确提取协议，检查 512×512 尺寸和类别编码，再读取类别值。本阶段仅核对了这 18 个掩膜的文件身份，没有读取载荷。
2. 检查掩膜与影像的对应、黑色边界、有效区域及严重损伤覆盖；未记录清楚时停止评分。零目标和技术失败场景保留。
3. 测量条件成立后，在本机运行固定感知器，最多 576 次局部观察；先比较随机初查、变化排序、简单阴性复核。保持 4×4 格、主预算 8、升级成本 2。

主指标拟为：已付费观察得到的严重损伤预测像素并集，与发布严重损伤参考像素的交集；同一像素只计一次。无参考目标场景的召回为 null。旧“4 像素＋10%轮廓”逐栋匹配规则和建筑数量效用不能直接用作面积奖励。

初步诊断不拟合目标事件参数，不把旧建筑数量报价解释成像素面积，不把参考掩膜交给在线策略。先报告三个事件各自的测量与发现机会；这批开发结果即使有收益，也不足以证明新方法或独立泛化。标注模型与感知器共享 xBD 来源可能带来偏差，须明确披露。

## 本地查看工具

`review.html` 支持查看原始成对 RGB、人工描画与草稿导出。由于当前没有标注资源，它保留作可视检查工具，全部真实场景仍未标注。浏览器交互验证使用独立的合成图，测试数据不会进入真实评价；所有 36 张真实 RGB 在浏览器中加载通过。

可以直接用浏览器打开本地 HTML；或在工作区启动仅限本机的服务：

```bash
python3 -m http.server 8766 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:8766/output/disaster_search_external_rgb18_v1/review.html`。导出的首轮草稿仍须另一名实际复核者处理分歧，不能直接通过最终真值校验。
