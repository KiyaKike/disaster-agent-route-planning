# 真实需求评估：已有闭环，尚未达到现场可用

2026-11-02。此前浏览器样例主要验证软件接口，不能据此证明灾后搜查有效。本轮已经用真实xBD灾前灾后影像、固定模型实际输出和发布严重损伤参考完成432条路线回放；没有再随机生成目标或误检漏检。

## 本轮真正增加的证据

保留既有三事件各12对、共36对影像，不换掉海啸零检出和其他失败场景。第一层使用真实前后64像素粗图的纹理与变化线索；第二层只接收已支付局部观察的真实模型预测。数据在原任务中已使用过，属于开发回放，不是新独立确认。

每幅图分别形成一个4×4搜查任务，三档共同预算、四种共同路线基线。新增10项测试，累计77项路线测试通过；576份缓存重新按原阈值解码，432条路线及费用重放通过。没有新训练、模型推理、影像下载或GPU费用。只补读84,672字节公共拍摄元数据。

## 真实数据没有支持当前简单反馈规则

240代理预算下，正确检出的严重发布参考像素召回如下。它是面积指标，不能直接解释为受损建筑数量或找到人员的比例。

| 事件 | 灾前纹理静态 | 灾后线索静态 | 在线重算但不传播 | 在线邻域反馈 |
|---|---:|---:|---:|---:|
| 尼泊尔洪水 | 33.10% | 32.11% | 32.11% | 22.23% |
| 巽他海啸 | 0% | 0% | 0% | 0% |
| 塔斯卡卢萨龙卷风 | 31.28% | 0% | 2.32% | 1.27% |

尼泊尔中，邻域反馈降低了受损区域覆盖和正确检出，假阳性也更多；不能因为地图会更新就宣称在线有效。龙卷风仅3/12有严重参考、2/12在当前模型下可检出，结果容易受个别场景影响；灾前纹理静态的较高分不证明灾前方法普遍更好。

海啸是明确的感知限制：灾前纹理路线覆盖了87.50%的严重参考像素，但正确检出仍为0；即使查看所有16格，固定模型也没有真阳性。模型完全漏掉的目标不能靠改路线获得正确检出。另一方面，灾后静态只有45.26%参考覆盖，邻域反馈为0覆盖，说明路线先验和错误反馈也存在问题。两种问题须分别保留，不能全部归给感知器。

三事件全网格可正确检出的严重参考上限分别53.57%、0%、47.01%，这只是付费限制取消后的模型上限，不是相同路线预算下的Oracle。不能把这些上限当作方法成绩。

本轮停止将该邻域传播基线作为主方法推进，不在这36对上继续选邻域、改权重或改阈值。结果也不否定其他在线规划方法；当前只有少量开发场景，尚未建立新方法贡献。

## 离真实需求还差什么

| 需求 | 本轮情况 | 剩余缺口 |
|---|---|---|
| 真实灾前灾后输入 | 已有36对真实影像，发布来源固定 | 尚非连续完整灾区；不能跨影像块随意连线 |
| 真实观测误差 | 使用固定模型真实局部预测 | 当前模型存在跨灾害完全漏检和误报 |
| 双层地图记忆 | 已付观测与原线索分开记录，并驱动简单决策 | 排名效用不是概率，纹理不是建筑/人口暴露语义图 |
| 空间路线闭环 | 移动、观察、规划、返程统一计费 | 距离为图内格宽、时间为代理预算，不是已验证米数和实际航时 |
| 可达性和安全约束 | 目前只有平面距离与预算返程约束 | 地形、道路中断、障碍、禁飞及平台动力学未接入 |
| 真实目标验证 | 使用发布严重损伤像素参考 | 不是新现场人工真值，也不直接评价人员/物资搜查 |
| Agent系统 | 确定性状态、记忆和行动循环已接通 | 实时传感器、定位、工具调用及执行平台未验证 |

补读的传感器GSD尚未证明等于PNG像元间距，数据也没有可直接使用的PNG地理变换，因此本轮没有把影像像素伪装成真实米数。单位限制是实际部署缺口，不影响同一图内、同一费用模型下的策略比较。

## 下一步仍围绕搜查路线

优先建立一个有地理参考的连续区域案例，接入有来源的灾前建筑/设施分布和符合平台的移动约束；保持两层地图、实际观测与独立评价的边界，再固定新的比较协议。灾损识别诊断仍单独保留，不以反复训练替代路线工作；当前无需先租GPU。
